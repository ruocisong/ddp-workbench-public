# Rights And Permissions

This note records the current verified rights posture for the **Antica Fiamma (AF)** public repository and live academic website. Release-specific statements for the archived version 1.0.0 remain recorded in [`../../RELEASE_NOTES.md`](../../RELEASE_NOTES.md) and [`../../SOURCE_PROVENANCE.md`](../../SOURCE_PROVENANCE.md).

## Source Relationship

Antica Fiamma uses the Dartmouth Dante Project (DDP) as its commentary source. The live interface and public documentation identify DDP as the source archive and AF as an additional scholarly reading environment. AF is not an official DDP publication and does not replace the source archive.

## Confirmed Permission Scope

The project author holds written authorisation for the current academic, non-profit website use of DDP-derived material in Antica Fiamma. Documentation of that authorisation is retained in the project's private records; this public note does not reproduce private correspondence or expand its terms.

The confirmed scope does **not** establish a general licence to redistribute the complete DDP-derived commentary corpus through GitHub, Zenodo, or another repository. Neither the public visibility of the authorised website nor the presence of deployable interface pages in this repository attaches the MIT or CC BY licence to DDP-derived content.

## Public Repository And Private Production Boundary

This living public GitHub repository contains project-owned source code, documentation, selected method-facing utilities, inspectable deployment-packaging code, rights-safe samples, and selected public interface materials.

Production deployment and active research development are operated from a separate private repository. The public repository is intentionally curated rather than mirrored from that private workspace. Private Git history, internal research material, source-sensitive inputs, review traces, generated runtime payloads, publication drafts, operational state, and private correspondence are not part of the public scholarly object merely because they exist in the production workspace.

The complete DDP-derived commentary payload is excluded from this public repository. Public release of any project-derived scholarly structure must not silently expand rights in the underlying source material.

## GitHub And Zenodo Release Boundaries

The Zenodo 1.0.0 archive is a narrower fixed snapshot than the living public GitHub repository. It omits generated author/work/personaggio pages that may cumulatively expose source-derived material. The complete DDP-derived commentary payload is excluded from both.

The Zenodo 1.0.0 release may include:

- project-owned HTML, CSS, JavaScript, and Python code;
- public methodological and technical documentation;
- deployment packaging and runtime checks;
- synthetic or redacted JSON examples;
- aggregate coverage counts that do not reproduce commentary text;
- project-created interface screenshots with source-sensitive reuse notes.

It excludes:

- the complete DDP-derived commentary payload;
- bulk commentary full text or reconstructable exports;
- third-party source files lacking a confirmed redistribution basis;
- private research files, publication drafts, snapshots, reports, caches, credentials, and deployment residue.

## Layered Licences

- Project-owned software: MIT.
- Project documentation by Ruoci Song: CC BY 4.0 unless otherwise noted.
- Synthetic/redacted structural samples: CC BY 4.0 as documentation, without rights in source materials.
- DDP-derived commentary and third-party materials: outside the repository licences; source-specific rights and the limited written website authorisation control.

## Safeguards

- DDP attribution remains visible.
- Source archive, poem, project code, and derived scholarly layers remain conceptually distinct.
- Heavy commentary payloads are excluded from GitHub and Zenodo.
- Samples use synthetic or redacted placeholders.
- Aggregate counts are labelled as runtime/interface units rather than independent commentary opinions.
- Public repository updates are selected for release rather than copied wholesale from private development history.
- A future broader release requires a separate rights review and cannot be inferred from the current repository or an earlier deposit.
